# getdata自动化平替

## 默认目标

给一张图，识别横纵坐标数字和曲线趋势点；如果图里只有离散点位，就直接提取这些数据点。最后必须在 Codex 回复里直接打印一个可复制进 Excel 的表格，不要把 Excel 文件作为结果给用户。

默认输出使用制表符分隔表格（TSV），放在代码块中。用户复制整个代码块内容到自己的 Excel 时，应能自动分列。

除数字、原始曲线符号和单位外，尽可能使用中文。结果不确定时，用中文简短说明哪里需要人工复核。

## 工作流

1. 直接观察图片，识别坐标轴标签、单位、刻度数字、图形类型、曲线或点位数量，以及多条曲线/点位是否共享同一个横轴或纵轴。
2. 判断表格结构：
   - 多条曲线共享同一坐标轴时，优先用统一坐标行。例如共享 `Depth(cm)` 时，用 `深度_cm` 作为第一列，每条曲线一个数值列。
   - 如果图里只有散点或独立点位，直接提取每个点，输出 `点位编号`、`横坐标数值`、`纵坐标数值`、`备注`。
   - 多条曲线无法自然对齐时，仍输出一个表格，但改用长表：`曲线名称`、`横坐标数值`、`纵坐标数值`、`备注`。
3. 为脚本创建校准 JSON。至少给出每个数值轴两个校准点：像素位置和真实数值。
4. 调用 `scripts/digitize_plot.py`，让脚本输出 TSV 表格到终端。为避免 Windows 管道转码，也可以加 `--tsv table.tsv` 写出 UTF-8 表格文本文件，再读取文件内容贴到最终回复里。
5. 如果需要视觉复核，可让脚本生成 `overlay_check.png`，但最终结果仍以 Codex 页面中的 TSV 表格为主。

## 校准 JSON

共享坐标轴的推荐格式：

```json
{
  "mode": "shared_axis",
  "shared_axis": {
    "column": "深度_cm",
    "orientation": "y",
    "ticks": [
      {"pixel": 76, "value": 0},
      {"pixel": 248, "value": 80}
    ],
    "sample_values": [0, 10, 20, 30, 40, 50, 60, 70, 80]
  },
  "series": [
    {
      "column": "δ13C_数值",
      "orientation": "x",
      "ticks": [
        {"pixel": 84, "value": -4},
        {"pixel": 126, "value": 0}
      ],
      "roi": [78, 70, 145, 252]
    }
  ]
}
```

长表的推荐格式：

```json
{
  "mode": "long",
  "x_axis": {
    "label": "横坐标数值",
    "ticks": [
      {"pixel": 80, "value": -4},
      {"pixel": 126, "value": 0}
    ]
  },
  "y_axis": {
    "label": "纵坐标数值",
    "ticks": [
      {"pixel": 76, "value": 0},
      {"pixel": 248, "value": 80}
    ]
  },
  "series": [
    {
      "name": "曲线1",
      "roi": [70, 70, 150, 252]
    }
  ]
}
```

散点或独立点位的推荐格式：

```json
{
  "mode": "points",
  "x_axis": {
    "ticks": [
      {"pixel": 80, "value": 0},
      {"pixel": 260, "value": 100}
    ]
  },
  "y_axis": {
    "ticks": [
      {"pixel": 240, "value": 0},
      {"pixel": 60, "value": 10}
    ]
  },
  "series": [
    {
      "name": "点位",
      "roi": [70, 50, 270, 250],
      "min_pixels": 3,
      "max_pixels": 200
    }
  ]
}
```

`roi` 是 `[left, top, right, bottom]` 像素范围。尽量只框住曲线，避开坐标轴、文字、标尺和图例。

## 脚本用法

```bash
python C:\Users\Lenovo\.codex\skills\getdata-auto-replacement\scripts\digitize_plot.py --image image.png --config calibration.json --outdir output
```

常用参数：

- `--tsv table.tsv`：把可复制表格写入 UTF-8 TSV 文本文件；需要保持中文和 `δ` 时推荐使用。这个文件只是为了让 Codex 稳定读取表格内容，不能替代最终回复里的表格。
- `--points 15`：长表模式中每条曲线保留约 15 个趋势点。
- `--threshold 150`：深色像素阈值；图片较淡时可调大。
- `--no-overlay`：不生成叠加检查图。

## 输出要求

最终回复中必须直接给用户一个 TSV 表格，格式如下：

```text
深度_cm	δ13C_数值	δ18O_数值	δ13Corg_数值	备注
0	-2.9	-8.0	-26.5	估计
10	-2.4	-7.6	-26.1	可靠
```

要求：

- 不生成 Excel 文件作为交付结果；不要只给文件路径。
- `--tsv` 只是中间文本文件，最终仍必须把表格贴在 Codex 页面里，让用户直接复制到自己的 Excel。
- 不输出多张表。
- 表格列名和备注用中文。
- 数字保留阿拉伯数字，不转中文数字。
- 如果只给了点位图，表格必须直接列出提取到的每个点位。
- `备注` 只用简单中文标记，例如：`可靠`、`估计`、`重叠不确定`、`坐标轴不确定`、`需人工复核`。
- 如果不确定性较大，在表格后用一两句中文说明需要复核的地方。

## 注意事项

- 本 skill 不依赖本地 OCR。轴数字由 Codex 视觉识别，脚本负责按校准点映射像素到数据值。
- 如果轴不是线性坐标，必须说明脚本默认不适用，除非用户明确提供转换方式。
- 如果图像太低清、曲线和文字严重重叠、或多条曲线无法区分，先输出可用草稿，再提醒人工复核。
